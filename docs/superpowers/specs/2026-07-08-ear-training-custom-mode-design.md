# 음감훈련 "커스텀" 모드 설계

작성일: 2026-07-08

## 배경 / 동기

레슨 선생님이 제안한 코드 청음 훈련 2단계:

1. 랜덤 코드를 들려주고 **코드의 성질**(메이저/마이너/어그멘티드/디미니시…)을 객관식으로 구분.
2. 키 하나를 스케일로 잡아 들려준 뒤, **랜덤 다이어토닉 코드 하나**를 친 것을 맞추기.

이 두 훈련은 이미 음감훈련 모드(`EarTrainingMode`) 안에 상당 부분 구현되어 있다.

- **3단계 코드 청음** (`ChordIdentify.tsx`) — 선생님의 1번과 동일. 다만 난이도가 **고정 프리셋 3개**(기초=maj·min / 3화음=maj·min·dim·aug / 7화음=maj7·m7·7·m7♭5)뿐이라 사용자가 직접 고를 수 없다.
- **4단계 진행 청음** (`ProgressionEar.tsx`) — 선생님의 2번과 비슷하지만 키를 잡은 뒤 **여러 코드(진행)**를 순서대로 맞히는 방식이며, "코드 딱 하나" 맞추기는 없다. 여기도 티어가 고정 프리셋(기초/팝/전체)이다.

핵심 요구사항: **"어떤 코드/도가 출제될지"를 사용자가 직접 옵션으로 고르고, 그에 따라 객관식 보기 개수도 줄어드는 커스텀 모드**를 추가한다. 예: 코드 청음에서 메이저·마이너만 체크하면 그 둘 중 하나만 들려주고 보기도 2지선다.

## 목표 / 비목표

**목표**
- 기존 두 스테이지(코드 청음 · 진행 청음)에 고정 프리셋과 나란히 "커스텀" 티어를 추가.
- 코드 청음 커스텀: 8개 코드 성질 중 원하는 것만 다중 선택 → 그 안에서만 출제, 보기도 그 개수만.
- 진행 청음 커스텀: ① 나올 도(degree) 다중 선택, ② 코드 개수(1·2·3·4) 선택. 개수 1을 고르면 선생님 2번("키 잡고 → 다이어토닉 코드 하나 맞추기")이 된다.
- 마지막 커스텀 선택을 `localStorage`에 저장해 다음 방문 시 복원.

**비목표 (YAGNI)**
- 새 스테이지/탭/컴포넌트를 만들지 않는다. 기존 스테이지의 시작 화면만 확장.
- 별도 "튜토리얼" 레벨 진행 흐름(통과 조건 등)은 만들지 않는다.
- 커스텀 세션은 lifetime 누적 통계에 기록하지 않는다(아래 참조).

## 설계

### 1. 데이터 모델 (`src/utils/earTrainingUtils.ts`)

실행 시점에는 "해결된 설정(resolved config)"만 있으면 되므로, 프리셋과 커스텀을 동일 인터페이스로 다룬다.

**코드 청음**
- `ChordIdentify`는 실질적으로 `qualities: ChordQualityId[]` 배열만 보고 동작한다(출제 후보 + 보기 버튼).
- 커스텀은 사용자가 체크한 `ChordQualityId[]`를 그대로 이 배열로 넘긴다. 별도 진행 생성 로직 불필요.

**진행 청음**
- 프리셋은 고정 진행 리스트(`progressions: number[][]`)에서 `pickProgression`으로 뽑는다.
- 커스텀은 고정 리스트가 없으므로 **선택한 도 안에서 무작위로 length개 생성**하는 헬퍼를 추가한다:
  ```
  buildCustomProgression(degrees: number[], length: number, last: string | null): number[]
  ```
  - length개를 `degrees`에서 무작위 추출(각 자리 독립 추출 허용).
  - 직전 시퀀스(`last`, `progressionSignature`로 비교)와 동일하면 몇 번 재시도해 회피.
  - length === 1이면 랜덤 도 하나 → 선생님 2번 동작.

### 2. 티어/설정 표현

- 각 스테이지 시작 화면에 4번째 버튼 "커스텀"을 추가한다.
- 커스텀 선택 상태와 사용자 체크 목록은 컴포넌트 로컬 state로 관리한다.
- 커스텀 여부는 tier id에 `'custom'`을 추가하거나(코드: `ChordTier['id']`에 `'custom'` 추가, 진행: `ProgressionTier['id']`에 `'custom'` 추가), 별도 boolean state로 표현한다. 구현 시 더 단순한 쪽을 택한다.

### 3. UI 흐름

시작 화면(난이도 선택)만 확장한다. "커스텀" 버튼을 누르면 그 아래 선택 패널이 펼쳐진다(체크 토글 그리드, 기존 버튼 스타일 재사용).

- **코드 청음 커스텀 패널**: 8개 성질 토글. 각 토글에 라벨(`chordLabel`) 표시.
- **진행 청음 커스텀 패널**: 도 1~7 토글 + 코드 개수(1·2·3·4) 선택.

**시작 게이트(유효성)**
- 코드: 최소 **2개** 선택해야 시작 가능(1개면 문제가 성립 안 됨).
- 진행: 도 최소 **2개** 선택 + 개수 1개 선택. (개수 1이라도 어떤 도가 나올지 몰라야 하므로 도는 2개 이상 필요.)
- 조건 미충족 시 시작 버튼 비활성화 + 안내 문구.

**복원**: 마지막 커스텀 선택을 `localStorage`에 저장하고 다음에 복원.
- 키 예시: `keymaster_earCustom_chord`, `keymaster_earCustom_progression`.
- 별도 유틸(예: `earTrainingUtils` 내 load/save 헬퍼) 또는 컴포넌트 내 처리. 잘못된/빈 값이면 기본값으로 폴백.

### 4. 통계 처리

커스텀은 난이도가 매 세션 달라 누적 정확도를 왜곡한다. 따라서:

- **커스텀 세션은 lifetime 누적(`earTrainingProgress`)에 기록하지 않는다.** `recordEarResult` 호출을 건너뛴다.
- 세션 통계(맞은 수/전체, 연속 streak)와 정답 공개/피드백은 프리셋과 동일하게 표시한다.
- 프리셋(기초/3화음/7화음, 기초/팝/전체)은 기존대로 기록한다.
- 이에 따라 "누적 X% · 최고 연속 N" 표시는 커스텀 세션에서는 숨긴다.

### 5. 손대는 파일

- `src/utils/earTrainingUtils.ts` — `buildCustomProgression` 추가, 커스텀 tier/검증 헬퍼, (선택) localStorage load/save 헬퍼.
- `src/components/ear/ChordIdentify.tsx` — 커스텀 티어 버튼 + 체크 패널 + 시작 게이트 + 커스텀 시 통계 기록 스킵.
- `src/components/ear/ProgressionEar.tsx` — 위 + 개수 선택 + `buildCustomProgression` 사용 + 통계 기록 스킵.
- 신규 컴포넌트 파일 없음.

## 엣지 케이스 / 에러 처리

- 커스텀 선택이 최소 조건 미달 → 시작 버튼 비활성, 안내 문구.
- `buildCustomProgression`에서 `degrees`가 1개뿐이거나 length가 범위를 벗어난 값이 들어와도 방어적으로 처리(호출 전에 UI 게이트로 막지만, 함수 자체도 clamp).
- localStorage 파싱 실패/빈 값 → 기본 프리셋 또는 빈 선택으로 폴백.
- 직전과 동일한 커스텀 시퀀스 회피는 best-effort(재시도 상한). degrees·length 조합상 회피 불가능한 경우(예: 도 2개 length 1) 중복 허용.

## 테스트

- `buildCustomProgression`: length 1/2/3/4에서 길이·구성 원소가 선택 도 집합 안에 있는지, 상한 재시도 후 반환하는지 확인.
- 유효성 게이트: 코드 <2개 / 진행 도 <2개일 때 시작 불가.
- 커스텀 세션에서 `recordEarResult`가 호출되지 않는지(통계 미기록) 확인.
- 수동 검증: 코드 청음에서 maj·min만 체크 → 2지선다로 출제되는지, 진행 청음에서 개수 1 → 단일 코드 도 맞추기로 동작하는지 브라우저에서 확인.
