# 코드톤 지판 연습 설계

작성일: 2026-07-16

## 배경 / 동기

기타 지판 위에서 **코드톤(chord tone)** 을 짚는 연습이 필요하다. 앱이 프렛보드 위에
시작 음 하나를 강조하면, 학습자는 거기서부터 코드톤을 **정해진 순서(7→1→3→5)로 한 칸씩**
짚어 아르페지오 모양을 완성한다.

핵심은 음 이름 암기가 아니라 **상대적 지판 모양(손가락 형태)** 을 몸에 익히는 것이다.
따라서 낮은 난이도의 채점은 "어떤 음인가"가 아니라 "시작점 기준 어느 칸인가"로 하고,
가장 높은 난이도에서는 **시작점 자체를 스스로 찾는** 연습을 한다.

기존 앱은 `튜토리얼 / 연습 / 음감 훈련` 3개 탭으로 구성되며, 음감 훈련 모드
(`EarTrainingMode`)가 "시작 화면(설정) → 진행 → 피드백" 구조와 `earTrainingProgress`
누적 통계, Tailwind 토큰(`surface`, `primary`, `glow-primary` 등)을 사용한다. 이 신규 기능도
같은 패턴을 따른다.

## 목표 / 비목표

**목표**
- 상단에 **새 탭 "지판"** 을 추가한다 (탭 순서: 튜토리얼 / 연습 / 음감 훈련 / 지판).
- 코드 퀄리티 **Maj7, min7** 두 개를 지원하고, 시작 화면에서 `Maj7 / min7 / 둘 다`를 토글로 고른다.
- **난이도 3단계**(고정)로 위로 갈수록 앱이 덜 알려준다.
- 코드톤을 **7→1→3→5 정해진 순서로 한 칸씩** 짚게 하고, 완성 시 아르페지오를 소리로 재생한다.
- 세션 정답률·연속 기록을 남긴다(`earTrainingProgress` 재사용).
- 마지막 설정(퀄리티 선택)을 `localStorage`에 저장해 재방문 시 복원.

**비목표 (YAGNI)**
- Maj7/min7 외 코드(Dom7, m7b5, 삼화음 등)는 지금 넣지 않는다. 셰이프 테이블만 늘리면 되므로 후속 확장 여지만 남긴다.
- 퀄리티당 셰이프는 **1개**만 정의한다(다른 현 세트/CAGED 포지션은 후속).
- 별도 튜토리얼 레벨 잠금/통과 흐름은 만들지 않는다.
- 왼손잡이 튜닝, 대체 튜닝, 프렛 사운드 커스터마이즈는 하지 않는다.

## 설계

### 1. 도메인 모델 (`src/utils/fretboardUtils.ts`)

**튜닝 / 음 매핑**
- 표준 튜닝 6현. 개방현 MIDI: `[E2=40, A2=45, D3=50, G3=55, B3=59, E4=64]`.
  현 인덱스 0 = 가장 낮은 6번줄(저음 E), 5 = 1번줄(고음 E).
- `(string, fret) → midi`: `openMidi[string] + fret`.
- `midi → pitchClass`: `midi % 12`. 채점(3단계)과 라벨 표시에 사용.

**코드 정의**
- 반음 오프셋(루트 기준): `Maj7 = [0, 4, 7, 11]`(1·3·5·7), `min7 = [0, 3, 7, 10]`(1·b3·5·b7).
- 짚는 순서는 도수 기준 `[7, 1, 3, 5]` 고정.

**보이싱 셰이프**
- 퀄리티마다 순서 있는 배열 하나. 각 원소는 `{ string, fretOffset, degree }`.
  - `string`: 절대 현 인덱스(0–5).
  - `fretOffset`: 셰이프 기준점(첫 음)의 프렛 대비 상대 칸. 기준점은 offset 0.
  - `degree`: 이 음의 도수(1/3/5/7). 배열 순서 = 짚는 순서(7→1→3→5).
- **전위**: 셰이프 전체 `fretOffset`에 앵커 프렛을 더하면 임의 키/위치로 평행이동. 셰이프 하나로 12키 커버.
- 셰이프는 한 음/한 현(4개 인접 현에 하나씩)을 기본으로 하며, 정확한 칸 값은 구현 시 `openMidi`와 코드 오프셋으로 검산해 표에 박아넣는다(테스트로 고정).

**앵커 생성**
- `pickAnchor(shape, minFret, maxFret)`: 셰이프 전체가 지정 프렛 범위(및 지판 0–15칸) 안에 들어오는 앵커 프렛을 무작위로 하나 고른다. 셰이프가 넥을 벗어나면 후보에서 제외.

**채점**
- 1·2단계(위치 고정): 클릭한 `(string, fret)`이 셰이프가 지정한 **정확한 칸**과 일치하는지.
- 3단계(시작점 찾기): 앵커를 강조하지 않으므로, 클릭한 음들의 **pitch class**가 해당 코드톤(1·3·5·7)과 맞는지로 채점. 단, 여전히 셰이프가 정의한 순서(7→1→3→5)와 한 옥타브 범위 안에서 형태가 성립하는지 확인한다.

### 2. 컴포넌트

**`src/components/fretboard/ChordToneFretboard.tsx`** — 연습 컨테이너
- 시작 화면: 설명 + `난이도 3단계` 선택 + `Maj7 / min7 / 둘 다` 토글 + 시작 버튼.
  (청음 모드 `ChordIdentify`의 시작 화면 UX를 그대로 참고.)
- 진행: 현재 문제(퀄리티·앵커·셰이프·요구 순서)를 상태로 들고, 사용자의 클릭을 순서대로 검증.
- 피드백: 완성 시 성공 표시 + 아르페지오 재생, `다음 →` 버튼. 세션 정답률·연속·누적 표시.
- 문제 생성: `weightedPick`류로 퀄리티 뽑고(둘 다 모드일 때), 난이도에 맞는 프렛 범위로 `pickAnchor`.

**`src/components/fretboard/Fretboard.tsx`** — SVG 지판 렌더 + 클릭
- 6현 × 0–15프렛(초기값, 조정 가능) 그리드. 넛/프렛 마커(3·5·7·9·12) 포함.
- props: 강조할 시작점, 이미 맞게 짚은 음들(초록), 힌트로 보여줄 남은 자리(1단계, 흐린 점 + 도수 라벨), 방금 틀린 음(빨강 플래시), `onFretClick(string, fret)`.
- 순수 표현 컴포넌트 — 채점/상태는 컨테이너가 소유.

### 3. 난이도 3단계 (고정)

1. **1단계 — 가이드**: 시작점 강조 + 남은 자리에 흐린 점·도수 라벨 표시. 순서대로 따라 짚기.
   앵커는 흔한 포지션(예: 5–9프렛)에서 생성.
2. **2단계 — 시작점만**: 앱이 시작점만 강조, 나머지 코드톤은 스스로 계산해 클릭.
3. **3단계 — 시작점 찾기**: 앱은 목표만 제시(예: "A현 근처에서 **Cmaj7**"). 시작점(루트/7도)을
   스스로 찾아 짚고 코드톤 완성. 넥 위치도 스스로. 채점은 pitch class 기준.

### 4. 채점 / 피드백 흐름

- 요구 순서(7→1→3→5)대로 **한 칸씩 클릭**.
- 기대 위치(1·2단계) 또는 기대 pitch class(3단계)와 맞으면 → 초록으로 채워지고 다음 도수 안내.
- 틀리면 → 빨강 플래시, 같은 도수 재시도(진행 안 넘어감).
- 4개 완성 → 성공 처리, `playMidiSequence`로 아르페지오 재생(`audioUtils`).
- `earTrainingProgress`에 결과 기록. `missKey`는 신규 축(예: `fretboardMisses`)을 퀄리티별로.

### 5. 진행/저장

- 세션 상태(정답/총문제/연속)는 기존 청음 모드와 동일 패턴.
- 누적 통계: `EarProgress`에 `fretboard` 스테이지 추가(또는 기존 구조 재사용). 구현 시 기존
  타입에 맞춰 최소 확장.
- `localStorage`: 마지막 퀄리티 선택·난이도를 저장/복원.

## 테스트 전략

- `fretboardUtils`의 순수 함수는 vitest로 단위 테스트(기존 `earTrainingUtils.test.ts` 방식):
  - `(string, fret) → midi`, `midi → pitchClass` 정확성.
  - 각 셰이프 전위 결과가 실제 코드톤 pitch class와 일치(코드 정의로 검산).
  - `pickAnchor`가 항상 지판 범위 안에 셰이프를 유지.
  - 채점 함수: 1·2단계(정확 칸)와 3단계(pitch class)의 정답/오답 케이스.
- UI 상호작용은 실제 앱 구동으로 확인(verify 스킬).

## 열린 사항 / 후속

- 퀄리티당 셰이프 1개 → 이후 다른 현 세트/CAGED 포지션, Dom7·m7b5·삼화음 추가는 셰이프 표 확장으로.
- 3단계 채점에서 "형태 성립" 판정의 엄밀도는 구현 중 실제 조작감을 보며 조정.
